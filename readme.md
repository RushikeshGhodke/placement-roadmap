## 1. Company Tiers

Not every company tests the same things. Know which tier you're aiming for, then prepare for that.

| Tier | What it means | Prep level |
|---|---|---|
| **Mass Recruiters** | Hire in large numbers, focus on aptitude + basics | Level 1 |
| **Product / Mid-tier** | Stronger DSA and CS fundamentals expected | Level 2 |
| **Dream / Super-dream** | Highest bar: hard DSA, projects, multiple interview rounds | Level 3 |

> You can move up between tiers. Many students start with Level 1 as a safety net and keep building toward Level 2 or 3.

## 3. How Selection Works

Most companies filter you through these stages, in roughly this order:

```
CGPA cutoff
   ↓
Resume shortlisting
   ↓
Aptitude round
   ↓
Coding tests
   ↓
Interviews
```

| Stage | What to know |
|---|---|
| **CGPA** | Many companies set an eligibility cutoff. Check it early. |
| **Resume shortlisting** | A clear, honest resume decides whether you get to the next stage. |
| **Aptitude** | Logical / reasoning / math, coding, and engineering fundamentals. |
| **Coding tests** | Usually multiple rounds, online or offline. |
| **Interviews** | Multiple rounds, online or offline. |

## 4. Preparation Plan

Each level **includes everything from the level before it.**

### 🟢 Level 1: Fundamentals *(Mass Recruiters)*

- [ ] **Aptitude:** Quant + Logical + Verbal
- [ ] **Coding:** 1 language, comfortable with the basics
- [ ] **CS fundamentals:** OOPs, DBMS, OS, CN basics
- [ ] **DSA basics:** arrays, strings, recursion, hashing
- [ ] **Resume v1** + clean LinkedIn profile
- [ ] **2 basic projects** based on fundamentals

### 🟡 Level 2: Alpha *(Product / Mid-tier)* `[+ Level 1]`

- [ ] **DSA:** linked list, stacks/queues, trees, sorting/searching
- [ ] **Faster aptitude:** timed practice, company-style OAs
- [ ] **SQL** + deeper OS/DBMS interview questions
- [ ] **2 solid projects**, explainable end to end
- [ ] **Resume:** impact-driven bullet points
- [ ] **LinkedIn:** active, with projects listed

### 🔴 Level 3: Sigma *(Dream / Super-dream)* `[+ Level 2]`

- [ ] **DSA:** graphs, DP, heaps, backtracking (medium to hard)
- [ ] **Contests:** LeetCode / CodeChef / Codeforces
- [ ] **System design basics** (LLD, plus HLD for some roles)
- [ ] **Internship or open-source contribution**
- [ ] **Mock interviews** with seniors/alumni
- [ ] **Referrals + networking**

## 5. Weekly System

The plan only works if you follow it consistently. This is a simple weekly rhythm, inspired by the ideas in *Atomic Habits*.

### Weekdays (Mon-Fri)

| Block | Time | Notes |
|---|---|---|
| **DSA** learn + practice | 1.5-2 hrs | Core block |
| **Aptitude** practice | 20-30 min | Short but daily, keeps it a habit |
| **Dev** | 30-45 min | Optional, if energy is left |

### Saturday: Learn + Build

| Block | Time |
|---|---|
| **Aptitude:** learn a new topic / shortcuts | 1 hr |
| **Project:** long coding session | 2-3 hrs |

### Sunday: Test + Review

| Block | Time |
|---|---|
| **Contest** (LeetCode weekly / CodeChef) | ~1.5 hrs |
| **Review mistakes** and plan next week | 30 min |

### 🧠 Habit rules that make it stick

- **Make it obvious:** fixed time and place; leave tomorrow's problem open.
- **Make it easy:** on a bad day, the minimum is 1 problem or 5 aptitude questions.
- **Make it satisfying:** keep a habit tracker and don't break the streak.
- **Never miss twice:** if you skip a day, don't skip the next one.
- **Build identity:** *"I'm someone who solves one problem every day."*

## 6. Mistakes to Avoid

| ❌ Mistake | Why it hurts |
|---|---|
| **Ignoring aptitude** | It is often the first filter, and strong coders get cut here. |
| **Mass-applying without prep** | Burns your chances and your confidence. |
| **Lying on the resume** | Interviewers dig into it, and it gets caught fast. |
| **Dead LinkedIn profile** | Recruiters and referrers check it. |
| **Rejection pressure** | One rejection is not a verdict. Review it, learn, move on. |
